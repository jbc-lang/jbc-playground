Files and projects

          
A project is the set of jBC files you’re working on. Use + to add a
            file, click a tab to edit it, and use Main to pick the file where
            execution starts. Try Status lookup (3 files) in the
            Example menu to see how multiple files fit together.

        

        

          
Link as routine

          
Check this on a separate file that declares a SUBROUTINE or
            FUNCTION your program uses. In Status lookup, caller.b
            is the main file, and linking get.status.b makes
            CALL GET.STATUS(...) work. Leave I_STATUS unchecked
            because $INSERT I_STATUS already brings it into the files that use it.

        

        

          
Run and stop

          
Run compiles the project and executes it in your browser if
            compilation succeeds. Click a diagnostic’s file and line to jump to it. For a
            program that uses INPUT, fill in Standard input
            before running. Stop cancels a build or stops a running program.

        

        

          
Colours and warnings

          
The editor colours statements, functions, strings, numbers, @
            variables, comments and labels as you type. It follows the jBC compiler's word
            lists but doesn't parse the program, so an unusual line may be coloured wrongly.
            A dotted red underline marks a statement the playground can't run, such as
            EXECUTE or OPENSEQ, and the line under the editor names
            them before you click Run.

        

        

          
Program limits

          
A build can include up to 32 files, 64 KiB of source per file, and 256 KiB of source
            total. A browser run has five seconds, 64 MiB of WebAssembly memory, and 64 KiB of
            combined output.

        

        

          
Save, load, and back up projects

          
    
            
  1. Enter a Project name and click Save to keep
              the current project in this browser.
    2. 
            
  2. Choose a name from Projects or type it directly. Click
              Load and confirm to open that save.
    3. 
            
  3. After you save or load a named project, changes autosave to that name.
              To save a copy under a different name, enter it and click Save.
    4. 
          

          
To back up a project or move it to another browser, click Export
            to download a file. Use Import to open a project file.

        

        

          
Where your work is stored

          
Everything stays in this browser. Your files are never uploaded: the compiler
            and your program run on this page, and the program has no network access.

          
    
            
  • The working draft, the files you see now with
              Main, linked routines and standard input, is kept in the
              browser's local storage as you type, and comes back when you reopen the page.
    • 
            
  • Named projects from Save are kept in the
              browser's IndexedDB database for this site.
    • 
            
  • Both belong to this browser profile on this device. Another browser, another
              profile or a private window does not see them, and a private window forgets them
              when it closes.
    • 
            
  • All tabs of the playground share the one working draft, so the tab you typed
              in last decides what the next visit shows. A named project that another tab
              changed is reported as a conflict instead of being overwritten.
    • 
            
  • Clearing this site's data in the browser settings deletes the draft and every
              named project. Use Export for anything you want to keep.
    • 
          

        

        

          
Running examples from the jBC guide

          
Examples in the jBC
            Programmers Reference Guide that the playground can build have a
            Run button. It opens the example here in a new tab:

          
    
            
  • The example arrives in the address after #, a part that the
              browser never sends to a server, and is removed from the address bar at once.
    • 
            
  • It opens as a single file named after the chapter, such as
              locate.b. It does not run until you click Run.
    • 
            
  • If the working draft it replaces had unsaved work, the playground keeps it:
              Restore previous draft appears next to Project
              name. Only the latest replaced draft is kept. Named projects are never
              touched, and the example is not saved into one until you click
              Save.
    • 
            
  • A Run link opened in a tab that already shows the playground asks before
              replacing the draft.
    • 
          

        

        

          
Reporting a problem

          
The bug button at the top opens a problem report on GitHub with the open file, your
            browser and this playground's build already filled in. They reach github.com in the
            form's address, and nothing is posted until you review the form and submit it. A long file is cut short; attach an
            Export file for a whole project. To suggest an idea, choose
            Idea among GitHub's issue forms instead.
